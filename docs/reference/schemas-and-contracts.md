# Facet Reference: Schemas and Contracts

This document provides a technical specification for all structured JSON schemas, contracts, and validation rules used across the Facet pipeline.

---

## 1. Specification Manifest Schema (`schema.json`)

- **Skill Location:** `.github/skills/technical-perception/schema.json`
- **Output Artifact:** `manifest.json` (Stage 1, created once via `create` and revised via scoped `edit`)
- **Governed By:** `@Researcher` (direct authoring), `@Formalist` & `@Auditor` (consumption)

### Top-Level Fields

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `concept_name` | string | Yes | Name of the algorithm, system, or mathematical concept. |
| `domain_category` | string | Optional | Subject domain (e.g. `"Complex Dynamics & Fractal Geometry"`, `"RFC Protocol"`). |
| `source_reference` | object | Yes | Canonical literature source with authors, title, year, and `doi_or_url` (or `"prompt://user_request"` in closed-book runs). |
| `target_interface` | object | Optional | Caller-mandated `target_module`, `entrypoints` (exact signatures & variadic `*args`/`**kwargs`), and `allowed_imports`. |
| `formal_specifications` | array | Yes | List of polymorphic formal specifications (`SPEC-k`). |
| `variables` | array | Yes | Domain variables with `symbol`, `domain`, `description`, and optional `dimensions`, `role` (`"input" \| "parameter" \| "output" \| "internal"`), and SI/dimensional `unit` tags. |
| `constraints` | array | Yes | Preconditions, domain bounds, and conservation laws. |
| `verification_contract` | object | Yes | Equivalence mode, precision, tolerances (`rtol`, `atol`), and invariant properties. |
| `ambiguities` | array | Required when `SOURCE_OCR.md` has uncertainty tags | Explicit ledger of notation ambiguities and `<uncertain>` / `<illegible/>` OCR findings. |

### Polymorphic Specification Object (`formal_specifications`)

```json
{
  "spec_id": "SPEC-1",
  "representation_format": "latex",
  "expression": "z_{n+1} = z_n^2 + c, \\quad z_0 = 0",
  "description": "Complex sequence generated by iterating f_c(z) = z^2 + c from the critical point.",
  "grounding_evidence": "Mandelbrot (1982), Chapter 3.",
  "epistemic_status": "canonical"
}
```

- Supported identifier aliases: `"spec_id"` or `"id"` (and `"expression"` or `"latex"`).
- Supported `representation_format`: `"latex"`, `"pseudocode"`, `"state_transition"`, `"bnf_grammar"`, `"predicate_logic"`, `"type_algebra"`, `"text_formula"`.
- Supported `epistemic_status`: `"canonical"` (literature-grounded), `"derived"` (proven extension), `"assumption"` (requires human sign-off at Checkpoint 1, including any claim derived from `<uncertain>` or `<illegible/>` OCR regions).

## 2. Mapping Document Schema (`mapping_schema.json`)

- **Skill Location:** `.github/skills/formal-mapping/mapping_schema.json`
- **Output Artifact:** `mapping.json` (Stage 2, created once via `create` and revised via scoped `edit` / `code_patch.py replace-json`; concrete `requirements.txt` packaging is owned by `@Engineer` in Stage 3)
- **Governed By:** `@Formalist` (direct authoring), `@Engineer` (implementation), `@Auditor` (verification)

### Top-Level Fields

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `concept_name` | string | Yes | Must match the `concept_name` from `manifest.json`. |
| `manifest_ref` | string | Yes | Reference to source manifest (`"manifest.json"`). |
| `public_interface` | object | Yes | Module name and entrypoint signatures (supporting variadic `*args`/`**kwargs` via `kind: "var_positional" \| "var_keyword"`) for cleanroom auditing. |
| `type_mappings` | array | Yes | Discrete computational type mappings (and optional physical `unit` tags verified against `manifest.json`) for continuous variables. |
| `operation_mappings` | array | Yes | Vectorized / algorithmic code constructs for theoretical operations. |
| `precondition_assertions` | array | Yes | Executable domain assertion strings placed at function entries. |
| `verification_obligations` | array | Yes | 4-predicate verification obligations (`OBL-j`) mapped from `SPEC-k`. |
| `anchor_test_cases` | array | Optional | Pinned test vectors for fast Stage 3 implementer smoke tests. |
| `algorithm_pseudocode` | array | Optional | Step-by-step computational pseudocode instructions. |
| `assumptions` | array | Optional | Conditioning, truncation, or domain boundary trade-offs. |
| `suggested_packages` | array | Optional | Suggested runtime/scientific packages for `@Engineer` to pin in `requirements.txt`. |
| `upstream_modules` | array | Optional | Seal-verified `specs/<spec_slug>/` Python modules verified against `PROVENANCE.json` and injected into Cleanroom `PYTHONPATH`. |

### Public Interface Object (`public_interface`)

```json
{
  "module_name": "mandelbrot",
  "entrypoints": [
    {
      "name": "mandelbrot_escape",
      "parameters": [
        {"name": "c", "type": "complex"},
        {"name": "max_iter", "type": "int"}
      ],
      "return_type": "tuple[bool, int]"
    }
  ]
}
```

### Verification Obligation Object (`verification_obligations`)

```json
{
  "id": "OBL-1",
  "source_spec_id": "SPEC-1",
  "predicate_type": "anchor",
  "formal_property": "mandelbrot_escape(0j, 100) == (True, 100)",
  "description": "Origin critical point c=0 remains bounded for all iteration limits.",
  "tolerance": "exact"
}
```

- Supported aliases: `"target_module"` or `"module_name"` in `public_interface`; `"obligation_id"` or `"id"`, `"spec_id"` or `"source_spec_id"`, and `"inputs"` or `"input"` in `verification_obligations`.
- Supported `predicate_type`: `"anchor"`, `"reference_model"`, `"relational_law"`, `"postcondition"`.
- Coverage & Interface-Consistency Rules:
  1. Every `spec_id` / `id` in `manifest.json.formal_specifications` must appear in at least one obligation's `spec_id` / `source_spec_id` (or `operation_mappings`).
  2. Every identifier-like input key referenced in `anchor_test_cases` or `verification_obligations[*].inputs` must be declared in `public_interface.entrypoints[*].parameters`.

## 3. Audit Feedback Schema (`audit_feedback_schema.json`)

- **Skill Location:** `.github/skills/verification-auditing/audit_feedback_schema.json`
- **Output Artifact:** `AUDIT_FEEDBACK.json` (Stage 4 when verification fails; aliases `defect_type` / `defect_category` / `classification` normalize to `failure_classification`)
- **Governed By:** `@Auditor` (direct authoring), `@Engineer` (Stage 3 bounded repair)

```json
{
  "timestamp": "2026-11-15T14:00:00Z",
  "concept_slug": "mandelbrot_iteration",
  "attempt_number": 1,
  "overall_status": "FAILED",
  "failures": [
    {
      "obligation_id": "OBL-3",
      "spec_id": "SPEC-2",
      "failure_classification": "IMPLEMENTATION_DEFECT",
      "minimal_counterexample": {"c": "2.1+0j", "max_iter": 100},
      "expected_oracle": [false, 1],
      "actual_observed": [true, 100],
      "violated_invariant": "exterior_radius: |c| > 2 escapes in <= 2 iterations",
      "diagnosis": "Loop condition checked magnitude after incrementing, missing early exit."
    }
  ]
}
```

- Supported status & defect aliases: `"overall_status"` or `"status"` (`"FAILED"` / `"FAIL"` requires a non-empty `"failures"` array; `"defects"` is automatically normalized to `"failures"` on save; `AUDIT_FEEDBACK.json` is preserved on disk across repairs and spec rewinds and archived to `specs/<slug>/AUDIT_HISTORY.json` at Stage 5).
- Supported `failure_classification`: `"IMPLEMENTATION_DEFECT"` (routes to `@Engineer` Stage 3), `"MAPPING_DEFECT"` / `"SPECIFICATION_AMBIGUITY"` (rewinds to `@Formalist` Stage 2, unsealing C2 while preserving all workspace artifacts and `AUDIT_FEEDBACK.json` on disk for scoped `edit` repair), `"MANIFEST_DEFECT"` (rewinds to `@Researcher` Stage 1, unsealing C1 & C2 while preserving all workspace artifacts and `AUDIT_FEEDBACK.json` on disk for scoped `edit` repair), and `"DOMAIN_BOUND_LIMITATION"`.

## 4. Pipeline Configuration Schema (`pipeline_config.schema.json`)

- **Skill Location:** `.github/skills/spec-pipeline/pipeline_config.schema.json`
- **Configuration File:** `.pipeline_config.json` (Optional workspace root file)

```json
{
  "governance_mode": "strict-4-gate",
  "max_repair_attempts": 3,
  "toolchain": {
    "verification_globs": ["verify_*.py", "test_*.py", "LOCAL_CRITIC.json", "AUDIT_FEEDBACK.json", "VERIFICATION.md"],
    "static_validator": "py_compile"
  },
  "scratch_retention": "consume-once",
  "approved_research_domains": [],
  "allow_web_research": true,
  "enable_local_spec_critic": "system1_s1_s2",
  "decision_model": {
    "enabled": true,
    "model": "pplx-decider-flash",
    "confidence_threshold": 0.85,
    "keep_alive": 0,
    "timeout_sec": 15
  },
  "enable_post_archive_embed": false,
  "upstream_seals": []
}
```

`allow_web_research: false` enables closed-book execution (deterministically blocking `web_fetch` and entering `STAGE_1_SPECIFICATION` directly when no visual `research/` assets require OCR). `enable_local_spec_critic` defaults to `"system1_s1_s2"` (boundary-only `<1 s` `pplx-decider-flash` semantic screening with `"keep_alive": 0` under `OLLAMA_MAX_LOADED_MODELS=1`, automatically falling back to `"off"` if disabled or offline; `"off"`, `"s2_only"`, and `"s1_and_s2"` are also supported). `upstream_seals` is an optional array of workspace-relative `PROVENANCE.json` paths that `@Facet` must view and `hypervisor-guard` must verify before `@Orchestrator` starts.

### Pipeline State, Tamper-Evident Seals, and Hook-State Lifecycle Snapshot

`.pipeline_state.json` (written atomically via unique `.tmp` + `os.replace` by `pipeline_guards.py`, which also emits a non-blocking `80 ms` loopback push to any open `Facet Lens` Canvas via `notify_facet_lens_sse()`) carries `current_stage` (`PRE_RUN_HALT`, `STAGE_*`, `CHECKPOINT_*`), `cycle_index`, `post_archive_halt_latch`, `repair_attempts`, `repair_history` (structured ledger of code repairs and upstream spec rewinds), `pending_rewind` (`target_stage`, `specialist`, `attempt`, and `Method L3` `localized_hunks`), `original_user_request`, `mandated_target_module`, `ocr_sha256`, `latest_stage_briefing` (persisted `26B-A4B` specialist `### Stage Briefing` narrative surfaced directly into `<checkpoint_briefing>`), `checkpoints` (`approved`, `approved_sha256`), `handshakes`, `last_archived_cycle` (`concept_slug`, `provenance_path`, `target_module`, `seal_sha256`, `archived_files`), `last_incident` (classified `errorOccurred` record: `quota_exceeded`, `empty_response_422`, `context_overflow`, or `other`, cleared once `@Facet` dispatches the recovery run), and `state_seal_sha256`.

| Seal | Computation | Verified by |
| :--- | :--- | :--- |
| `state_seal_sha256` | Tamper-evident SHA-256 of the canonical JSON (sorted keys, compact separators) of `.pipeline_state.json` excluding the seal field | `hypervisor-guard`, `facet-stop` |
| `PROVENANCE.json` `seal_sha256` | Same canonicalization over `PROVENANCE.json` excluding `seal_sha256` (including `hook_state_snapshot.json` in `artifact_hashes`); requires `"status": "VERIFIED_COMPLETE"` | `hypervisor-guard` (`upstream_seals`), `facet-stop` |
| Shadow Seal Ledger | `$COPILOT_HOME/session-state/seal_ledgers/seal_<sha256(cwd)[:24]>.json` mirrors `state_seal_sha256` and every `PROVENANCE.json` `seal_sha256` outside the workspace for tamper-evident parity | `verify_workspace_cryptographic_seals()` (parity required when an entry exists) |

#### Archived Hook-State Snapshot (`hook_state_snapshot.json`) & Next-Turn Cleanup
Rather than using clock-based pruning on `$COPILOT_HOME/session-state/hooks_state.json`, Facet cleans up subagent tracking state strictly at the end of a run's lifecycle:
1. **Snapshot at Archival or `/reset`:** `archive_completed_run()` and `snapshot_and_clean_interrupted_run()` walk `parent_session_id` upward to the root session and downward to all descendants, writing `hook_state_snapshot.json` into `specs/<concept_slug>/` (hashed into `PROVENANCE.json` `artifact_hashes` before `seal_sha256` is computed) or into `specs/<concept_slug>_interrupted_<timestamp>/`. The snapshot records only a 7-key whitelist (`parent_session_id`, `active_agent`, `failures_by_tool`, `consecutive_failures`, `consecutive_stop_blocks`, `audit_feedback_counted`, `previous_parent_agent`) and excludes `last_failed_args`, `last_web_fetch_sig`, `pending_prompt_command_receipt`, and any prompt text so git-tracked `specs/` bundles never capture file contents or paths. Under `autonomous-batch`, archival runs inside `@Auditor`'s `subagentStop` while `@Orchestrator` is still running, so `@Orchestrator`'s entry is captured mid-flight and kept intact until the turn finishes.
2. **Removal at the Next Human Turn:** Completed runs record `pending_state_cleanup` on the root entry and remove those descendant entries on the **next human turn** (`userPromptSubmitted` at depth 0), keeping the root session entry for Cycle 2. Explicit `/reset` (already a human turn) removes descendant entries immediately; CLI `reset` with no `sessionId` skips snapshot and cleanup cleanly. Entries from abandoned or hung chats that never reach archival or `/reset` are left in place (small and inert).

## 5. Implementation Lint Rules (`lint_rules.json`) & AST Contract Checks

- **Skill Location:** `.github/skills/implementation-engineering/lint_rules.json`
- **Enforced By:** `pipeline_guards.py` (`validate_python_ast` in `postToolUse` and `code_patch.py`) + `@Engineer` skill guidance

### Deterministically Checked by `validate_python_ast()`:
1. Module-level docstring present (at top of module or immediately after `from __future__ import annotations`) citing canonical literature (authors/year, equation, RFC, DOI, or URL).
2. Zero calls to undefined bare local helper functions (`NameError` / incomplete refactor guard across builtins, imports, parameters, and assignments).
3. 100% type annotations on all public function parameters (`posonlyargs`, `args`, `kwonlyargs`, `*args`, `**kwargs`) and return types, with zero unconstrained `Any`.
4. Zero raw floating-point equality (`==` / `!=`) comparisons against float literals (require `math.isclose` or `numpy.allclose`).

### Guided by `lint_rules.json` & `@Engineer` Instructions:
5. `from __future__ import annotations` and `NDArray[np.float64]` / dataclass typing conventions.
6. Per-function equation citations (`Implements Eq. (X.Y), Page Z`) and entry precondition assertions (`np.isfinite`, shape/domain bounds).

## 6. Multimodal OCR Provenance Contract (`SOURCE_OCR.md`)

- **Staging Helper:** `.github/skills/technical-perception/scripts/prepare_visual_sources.py`
- **Output Artifact:** `SOURCE_OCR.md` (Stage 0V, created once via `create` after staged plate inspection and revised via scoped `edit`)
- **Governed By:** `@Scribe` (authoring), `@Researcher` (consumption), `pipeline_guards.py` (`detect_ocr_uncertainties` gate)

### 3-Tier TEI P5 Epistemic Transcription Rules
1. **Tier 1 — Legible Math (Zero XML Tags):** Normalize Unicode ligatures (`ﬁ -> fi`, `ﬂ -> fl`) and double-bar norms (`\lVert x \rVert_{W}`) into standard LaTeX without emitting XML tags.
2. **Tier 2 — Contextual Reconstruction (`<uncertain>`):**
   ```xml
   <uncertain raw="-3l25/100000" guess="-3125/100000" reason="glyph_1_l_confusion" confidence="high">-3125/100000</uncertain>
   ```
3. **Tier 3 — Irrecoverable Occlusion (`<illegible/>`):**
   ```xml
   <illegible context="convergence_tolerance_rtol_exponent" reason="occluded"/>
   ```
- **Deterministic Propagation Gate:** Whenever `SOURCE_OCR.md` contains one or more `<uncertain>` or `<illegible/>` tags, `postToolUse` rejects `manifest.json` unless `ambiguities` is non-empty and at least one affected specification entry sets `"epistemic_status": "assumption"` (which also forces human sign-off at Checkpoint 1 under `autonomous-batch`).
