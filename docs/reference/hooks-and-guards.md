This document specifies the deterministic hook architecture implemented in `pipeline_guards.py` (CLI & symbol facade) and the 9-layer acyclic `facet_guards/` package, registered via `pipeline-guards.json` across GitHub Copilot in Visual Studio Code.

| Layer | Module | Responsibility |
| :---: | :--- | :--- |

On an Apple Silicon M5 Pro (64 GB), `pipeline_guards.py` measures a median **`58 ms`** standalone `python3` startup (`~0.2 ms` handler logic, invariant to `hooks_state.json` size) and **`151 ms`** median (`166 ms` max) end-to-end `preToolUse` duration in the Copilot session log (`133 ms` `userPromptSubmitted`, `130 ms` `userPromptTransformed`, `225 ms` `sessionStart`), staying two orders of magnitude below the `5–15 s` fail-open timeout thresholds.

## 2. Scope-Aware Precedence and Dual-Hook Idempotency

When Facet is installed at both the workspace level (`.github/hooks/`) and user level (`~/.copilot/hooks/`), Copilot dispatches both hooks for every event. Facet resolves this in two layers:

### Layer A: Scope-Aware Precedence Shadowing
- Workspace hooks pass `--scope workspace`.
- User hooks pass `--scope user`.
- When `pipeline_guards.py` executes with `--scope user`, it inspects `<cwd>/.github/hooks/pipeline-guards.json`. If an active workspace hook exists (and `disableAllHooks` is not true), the user hook immediately yields (`{}`) in less than 1 millisecond.

### Layer B: Secondary Atomic POSIX Event Lock
For concurrent calls or single-source dispatches:
- A SHA-256 event fingerprint is derived from:
  $$\text{hash} = \text{SHA-256}(\text{sessionId} + \text{action} + \text{timestamp} + \text{toolName} + \text{agentName})$$
- The hook attempts an atomic file creation:
  `os.open("~/.copilot/session-state/hook_locks/<hash>.lock", os.O_CREAT | os.O_EXCL | os.O_WRONLY, 0o600)`
- If the file exists (`FileExistsError`), another instance has already claimed the event, and the process exits immediately with `{}`. Stale locks (>15s) are purged automatically.

### Layer C: Two-Layer State Concurrency Locking & Atomic Unique Temp Files
Parallel tool calls (e.g., batched `view` reads) run concurrent hook processes. `pipeline_guards.py` prevents torn reads and lost updates across both same-session and cross-session races using two `fcntl.flock` layers (degrading gracefully to unlocked on non-POSIX hosts, with a `1.5 s` per-lock timeout that logs to `stderr` and never writes to JSON `stdout`):
1. **Striped Handler Serialization:** `invocation_state_locks()` acquires an exclusive `flock` on a 64-slot session stripe (`$COPILOT_HOME/session-state/state_locks/sess_00..63.flock`) strictly before a 64-slot workspace stripe (`ws_00..63.flock`) for the ~`0.2 ms` handler duration (`state_locks/` is separate from `hook_locks/` so 15-second event-lock cleanup never unlinks active `flock` inodes).
2. **Global Merge-Write Lock:** `save_session_state()`, `snapshot_session_tree_state()`, and `purge_session_state_entries()` acquire `$COPILOT_HOME/session-state/state_locks/hooks_state_global.flock`, re-read `hooks_state.json`, update only the target session keys, and commit via `atomic_write_text()` using unique `<pid>.<time_ns>.tmp` files + `os.replace()` (also used for `.pipeline_state.json`, Shadow Seal Ledgers, `PROVENANCE.json`, and config writes).

## 3. Capability Confinement and Security Guards

`preToolUse` enforces strict least-privilege boundaries across both file-editing tools (`edit`, `create`, `str_replace_editor`, `apply_patch`) and shell execution (`execute`, `bash`, `powershell`, `Bash`):

### 00. Hypervisor Read-Only Confinement, Handoff Briefs & Checkpoint Front Gates (`hypervisor-guard`, `facet-prompt`, & `facet-stop`)
`@Facet` declares the 6-category ceiling `tools: ['read', 'edit', 'execute', 'search', 'agent', 'web']` solely so Depth-1 `@Orchestrator` and Depth-2 specialists (`@Scribe`, `@Researcher`, `@Formalist`, `@Engineer`, `@Auditor`) inherit `bash`, `create`, `edit`, `grep`, `glob`, and `web_fetch` under Copilot SDK `1.0.108+` transitive parent-to-child tool intersection (setting `['read', 'agent']` at Depth 0 intersects `@Scribe` down to a single `view` tool, while omitting `'todo'` eliminates `update_todo` schema bloat across all roles). Depth-0 routing ignores stale `active_agent` state (`is_depth0_session`), denies direct depth-0 worker launches (`[HYPERVISOR INGRESS REQUIRED]`), and enforces root-only provenance on `/approve`, `/reset`, and `/add-source`. Agent-scoped hooks in `facet.agent.md` enforce:
- `hypervisor-guard` (`preToolUse`): verifies `.pipeline_state.json`, approved-checkpoint hashes, `upstream_seals`, and tamper-evident Shadow Seal Ledger parity deterministically in Python on every synchronous `task(agent_type="Orchestrator", mode="sync", ...)` call (eliminating redundant per-turn `view(.pipeline_state.json)` tool round-trips while keeping optional read-only `view` access confined to seal/provenance and pending checkpoint deliverables). Denies `glob`, `grep`, or workspace-folder `view` calls with the exact corrected `@Orchestrator` handoff call so `@Orchestrator` and `@Scribe` perform all folder/image discovery. At any `CHECKPOINT_*` stage (`checkpoint_handoff_gate`), `task`, `agent`, `write_agent`, and `send_message` are denied (`read_agent` remains allowed) and workers are restricted to read-only tools. Enforces `agent_type="Orchestrator"` and `mode="sync"` strictly and denies a first non-canonical prompt once with the exact 4-line (`Goal:`, `Context:`, `Allowed:`, `Expected:`) + `<user_request>` call so `@Facet` copies it cleanly (allowing a same-turn retry with `Orchestrator` + `sync` to prevent deny loops, and clearing `last_incident` upon dispatch).
- `facet-prompt` & `user-prompt-transformed`: handle `/status` (and fuzzy typos like `/stauts`) with an instant zero-tool `<status_pulse>` readout, replace non-`/approve` checkpoint inputs up front with a split-plane `<checkpoint_reprompt>` block (instant zero-tool hint on `/appove` or `approve/` `difflib` typos, or safe read-only Checkpoint Q&A on substantive questions about the pending deliverable), pre-render the exact `@Orchestrator` handoff call with a `STAGE_SPINNER_LABELS` `description` (plus Cycle-2 `specs/<prev_slug>/` context when referenced) inside `<hypervisor_context>` Step 1 & Step 2, inject `<recovery_notice>` after recorded `errorOccurred` incidents, and pair with `subagentStop` (`Orchestrator`) to deliver pure, tag-free user-facing Markdown checkpoint briefings (stage- and SHA-256-bound `26B-A4B` specialist briefing from `.pipeline_scratch/stage_briefings.json` with zero cross-stage `"latest"` fallback, cross-stage lexical overlap & self-talk filtering, `C1` display-math table de-duplication, and rich artifact-backed fallback prose, 3-column stage visual previews, `%20`-encoded file links, and a Style A `Stage X of 4` review card with geometric progress dots, 12-character `sha256` badge, `After Approval:` preview, and a `> ---` framed action bar `Reply /approve to continue · /reset to start over · or ask a question`) on checkpoint stops. Prompts and hook-injected blocks are **never capped or truncated**; to monitor context utilization against `num_ctx` (`131072`), inspect `inputTokens` in `session.usage_record` entries inside `~/.copilot/session-state/<session-id>/events.jsonl`.
- `facet-stop` (`agentStop`): enforces the Streaming Non-Duplication Invariant (never re-emitting prose for cosmetic formatting once tokens have streamed to VS Code Chat), allows zero-tool `<status_pulse>` replies, blocks premature exits when an active user request has not yet dispatched `@Orchestrator`, verifies post-archive `PROVENANCE.json` reads/seals, ensures a fenced `@Facet ...` next-cycle prompt at Stage 5, and ensures checkpoint `/approve` Gate Card presence. Read-only Canvas tools (`list_canvas_capabilities`, `open_canvas`, `invoke_canvas_action`) are permitted via `BENIGN_TOOLS`.

### Opt-In Redacted Hook Trace (`FACET_HOOK_TRACE=1`)
Setting `FACET_HOOK_TRACE=1` appends one redacted JSON line per hook invocation (including yielded user-scope calls) to `$COPILOT_HOME/session-state/hook_trace.jsonl` containing only `{ts, action, scope, sessionId, agentId, agentType, parentAgentId, toolName, mode, targetAgent, decision, outputKeys}`—never prompt text, file contents, or `stdout`.

### 0. Coordinator Privilege Separation (`coordinator-guard`, `orchestrator-prompt`, & `orchestrator-stop`)
`@Orchestrator` declares the 6-category ceiling (`read`, `edit`, `execute`, `search`, `agent`, `web`) so spawned child subagents inherit `create`, `edit`, `bash`, and `web_fetch` in Copilot SDK `1.0.108+` without `todo` schema overhead. Agent-scoped inline hooks in `orchestrator.agent.md` invoke:
- `coordinator-guard` (`matcher: "create|edit|str_replace_editor|apply_patch|bash|read_bash|stop_bash|list_bash|powershell|web_fetch|skill|rename_chat"`), deterministically blocking `@Orchestrator` from directly mutating files, running shell commands, fetching URLs, loading worker skills, or invoking unavailable client tools (`rename_chat`);
- `orchestrator-prompt` (`userPromptTransformed`) to strip unreachable `rename_chat` `<system_reminder>` blocks and inject Turn-0 `<stage_anchor>` routing strictly on `@Orchestrator` without affecting general or `[[PLAN]]` chats; and
- `orchestrator-stop` (`agentStop`) to reconcile mid-turn `"delivery": "steering"` `/approve`, `/reset`, and `/add-source` commands from `transcriptPath` and block premature archival claims when `.pipeline_state.json` still awaits human sign-off.

### 1. Vision & PDF Modality Firewall and `@Scribe` Orthogonal Channel Confinement
- `@Researcher`, `@Formalist`, `@Engineer`, and `@Auditor` are deterministically blocked from calling `view`/`read_file` on `.png`, `.jpg`, `.jpeg`, `.webp`, `.gif`, `.bmp`, `.tiff`, and `.pdf` assets (`[MODALITY FIREWALL]`), consuming normalized `SOURCE_TEXT.md` (`1..N` embedded PDF prose/tables/references with `<details>`-quarantined 2D glyph clusters) alongside `@Scribe`'s 1-plate-at-a-time visual `SOURCE_OCR.md`.
- `@Scribe` is confined strictly to Stage 0V visual transcription: `bash` permits only single invocations of `prepare_visual_sources.py` (no `;`, `&&`, `||`, `|`, `>`), reading `SOURCE_TEXT.md` is blocked (`[CHANNEL ORTHOGONALITY]`), `view` enforces strictly **1 visual plate at a time** in `staging_manifest.json` order (`[SINGLE-PLATE OCR GATE]`), file mutations permit only `SOURCE_OCR.md` (single-plate) or `.pipeline_scratch/ocr_staging/plates/<plate_stem>.md` (`create` per plate for $M \ge 2$, `edit` only for in-place XML fixes, deterministically assembled into `SOURCE_OCR.md` once all `M/M` plates validate), and delegating to `Scribe` in `STAGE_2_MAPPING`+ is blocked.

### 2. Control-Plane Immutability, Create-Once / Scoped-Edit Sandboxes, `AST-1..4` Gates & 4-Stage `edit` Auto-Snap
- Subagents (`@Researcher`, `@Scribe`, `@Formalist`, `@Engineer`, `@Auditor`) are strictly barred from modifying `.pipeline_config.json`, `.pipeline_state.json`, `approved_sources.json`, `pipeline-guards.json`, `pipeline_guards.py`, or `.pipeline_scratch/*` (with the sole exception of `@Scribe` writing isolated `ocr_staging/plates/<plate_stem>.md` transcripts during Stage 0V).
- Deliverables follow **Create-Once, Scoped-Edit Thereafter** (`[SCOPED EDIT REQUIRED — PRESERVE EXISTING ARTIFACT]`): new specification and implementation files inside `<cwd>` (out-of-workspace files are ignored by `postToolUse`) are written once via `create` (with `.rollback_<filename>` backups staged automatically and misplaced `from __future__ import ...` lines hoisted deterministically before `py_compile`), and all local validation or Stage 4 Reflexion updates preserve existing files on disk and apply minimal targeted changes via `edit` (with format-symmetric `resolve_edit_pair()` whitespace, indentation, JSON, docstring, import-block, AST-symbol, and whole-module auto-snapping) or `code_patch.py` (`replace-symbol`, `replace-lines`, `replace-json`).
- Four deterministic AST verification gates guard artifact quality: **`AST-1`** (`formal_predicate` Python `eval` AST compilation + $O(N^3)$ decomposition ban in `precondition_assertions`), **`AST-2`** (`find_lexical_unbound_names` lexical scope check across functions, closures, comprehensions, and `except` handlers), **`AST-3`** (`detect_rational_pole_sign_clip` blocking silent one-sided rational denominator bailouts in `preToolUse`), and **`AST-4`** (caller `mandated_target_module` parity, exact positional parameter names, `verify_*.py` entrypoint call coverage, and `AST-4d` `math.isclose` `rtol`/`atol` `TypeError` check).
- At stage-transition boundaries (`subagentStop` / Stage 0V pre-check), AST-risk-gated (`ast_risk_gated`) `pplx-decider-flash` (`/v1/systemone`, `"keep_alive": 0`) performs `<1 s` semantic spec screening (`"system1_s1_s2"`, $\tau=0.85$, skipping 3rd-model loads when deterministic AST risk checks are clean), Stage-4 diagnosis-vs-label override, and `Method L3` (`Line-ID Choice` + AST/JSON hunk mass pooling + Companion `Noul`) localization to populate advisory `<edit_scope_hint>` windows, degrading gracefully to `"off"` if offline or disabled.

- `@Engineer` modifies only `requirements.txt` (`create`/`edit`, PEP-508 validated) and production source code (`*.py`), symmetrically barred from reading, modifying, or executing verification oracle scripts (`verify_*.py`, `test_*.py`, or `pytest`) via `view`, `grep`, or `bash`.
- `@Auditor` writes/edits only verification test files (`verify_*.py`, `test_*.py`, preserved against `rm` or full-file `create` overwrites on re-audits), writes `VERIFICATION.md` or `AUDIT_FEEDBACK.json` via `create`, and under default `two_phase_post_pytest` is denied `view`/`grep` or shell `cat`/`head`/`tail` source reads on `<target_module>.py` until after a failing `pytest` run unlocks root-cause defect triage (receiving `<verification_ready>` immediately on a passing `pytest` run to proceed straight to `VERIFICATION.md`).
- **Linearizable State, Outer-vs-Inner Hook Timeouts & `stop_hook_active`:** Session and stage-receipt updates execute under lock-held read-modify-write transactions (`update_session_state`, `update_stage_receipts`) safe across parallel tool batches; outer hook `timeoutSec` budgets (`postToolUse: 30`, `userPromptSubmitted: 30`, `subagentStop: 15`, `agentStop: 15`) strictly bound all inner subprocess/HTTP timeouts to prevent fail-open cutoffs; and `agentStop`/`subagentStop` honor Copilot's native `stop_hook_active` continuation flag.

## 4. Reflexion Bounded Self-Repair & Target-Aware Spec Rewind Loop

`postToolUse` on `AUDIT_FEEDBACK.json` and `subagentStop` on `@Auditor` manage target-aware repair and upstream specification rewinds:
1. If `AUDIT_FEEDBACK.json` reports `"overall_status": "FAILED"` (or `"status": "FAILED"` / `"FAIL"`), the hook increments `fsm["repair_attempts"]` and appends a structured entry to `fsm["repair_history"]` while **preserving `AUDIT_FEEDBACK.json` on disk** (archived to `specs/<slug>/AUDIT_HISTORY.json` at Stage 5).
2. If `repair_attempts < max_repair_attempts` (default: 3), `apply_audit_rewind_transition()` routes by `failure_classification`:
   - **`IMPLEMENTATION_DEFECT` / `DOMAIN_BOUND_LIMITATION`:** Transitions FSM to `STAGE_3_IMPLEMENTATION` (`@Engineer` surgical code repair with `repair_history` credit ledger).
   - **`MAPPING_DEFECT` / `SPECIFICATION_AMBIGUITY`:** Unseals `checkpoint_2` while **preserving all workspace artifacts on disk** (`mapping.json`, `requirements.txt`, `*.py`, `verify_*.py`, and `AUDIT_FEEDBACK.json`), transitions FSM to `STAGE_2_MAPPING` (`@Formalist` applies a scoped `edit` to `mapping.json` with `<original_user_request>` + `<audit_rewind_feedback>` injected via `modifiedArgs["prompt"]`), and resumes the deterministic lifecycle forward.
   - **`MANIFEST_DEFECT`:** Unseals `checkpoint_1` and `checkpoint_2` while **preserving all workspace artifacts on disk**, transitions FSM to `STAGE_1_SPECIFICATION` (`@Researcher` applies a scoped `edit` to `manifest.json`), and resumes the deterministic lifecycle forward.
   - `VERIFICATION.md` requires a recorded passing `pytest` run matching current suite/module SHA-256 digests, blocks any `OBL-j: FAIL/FAILED` or `CONDITIONAL_PASS`, and records `## Specification & Repair History` whenever prior repairs or spec rewinds occurred.
3. If `repair_attempts >= max_repair_attempts`:
   - The **Reflexion Circuit Breaker** trips (`CHECKPOINT_REPAIR_ESCALATION`) and halts for human oversight.
